# AI Agentic Development Visualizer v2 — 설계 문서

- 날짜: 2026-08-08
- 상태: 사용자 승인 완료 (구두 설계안 기준), 스펙 검토 대기
- 대상 코드베이스: `e:\TEST` (정적 웹 앱 — index.html / styles.css / app.js)

## 1. 배경과 목표

AI Agentic Development의 모습을 일반 관객에게 영상으로 보여주기 위한 **연출용 시뮬레이터**를 만든다.
실제 AI 세션을 녹화하는 대신, 과정을 스크립트된 애니메이션으로 재생하는 데모 앱을 촬영한다.

발표자가 프리셋 주제를 고르고 시작 버튼을 누르면 다음 5단계가 자동 재생된다:

1. Intent & Planning — 요구사항 해석과 기획서(구현 계획) 작성
2. Sub-Agent Allocation — 오케스트레이터가 서브에이전트에게 작업 분배
3. Code Generation — 에이전트들이 병렬로 코드 작성 (타이핑 스트림 연출)
4. E2E Verification — 브라우저 테스트, 실패 → 자가치유 → 재실행 → 통과
5. Final Product — 완성된 앱 프리뷰 공개

기존 v1 앱을 업그레이드한다. v1의 치명적 약점 세 가지를 해소하는 것이 핵심이다:

- 콘텐츠가 습관 트래커로 하드코딩 → **시나리오 3종 완전 지원**
- 코드 생성 단계가 로그 2줄 → **코드 타이핑 스트림 탭 신설**
- 러닝타임 고정 ~20초 → **속도 조절·일시정지·리셋 컨트롤**

| 결정 항목 | 선택 |
|---|---|
| 촬영 방식 | 실제 세션 녹화가 아닌 **연출용 시뮬레이터** |

## 3. 아키텍처

### 3.1 원칙: 콘텐츠와 엔진의 분리

v1은 재생 로직(async 함수) 안에 습관 트래커 대사와 HTML이 박혀 있다.
v2는 **시나리오 데이터(무엇을 보여줄지)** 와 **재생 엔진(어떻게 재생할지)** 을 분리한다.

```
e:\TEST\
├── index.html      # 레이아웃 + 재생 컨트롤 바 + Code Stream 탭 추가
├── styles.css      # 컨트롤 바, 코드 패널, 타이핑 커서 스타일 추가
├── scenarios.js    # (신규) 순수 데이터 — 시나리오 3종의 모든 콘텐츠
└── app.js          # (개조) 범용 타임라인 플레이어 + UI 렌더러
```

빌드 도구 없음. `<script src="scenarios.js">` 를 `app.js`보다 먼저 로드하는 전역 변수 방식 유지.

### 3.2 시나리오 데이터 스키마 (`scenarios.js`)

```js
const SCENARIOS = {
  habit: {                    // key = 프리셋 id (habit | kanban | crypto)
    label: '습관 트래커 App',   // 프리셋 칩 문구
    prompt: '...',            // 프롬프트 입력란에 채워질 요구사항 문장
    appName: 'Modern Habit Tracker',

      { title: '2. Sub-Agent Work Distribution', html: '...' },
      { title: '3. Verification Strategy', html: '...' },
    ],

    // 2단계: 배분 로그 대사 (agent: orchestrator|planner|ui|dev|qa)
    delegationLogs: [ { agent: 'ui', text: '...' }, ... ],

    // 3단계: 코드 스트림 — 에이전트별 파일, 순서대로 번갈아 타이핑
    codeFiles: [
      { agent: 'ui',  filename: 'styles.css', code: '...' },
      { agent: 'dev', filename: 'app.js',     code: '...' },

        { console: '> Step 1: ...', cursor: { top: '40%', left: '45%' } },

      ],
```

렌더링에 쓰이는 HTML 조각은 신뢰된 정적 데이터이므로 innerHTML 사용을 유지한다(v1과 동일).

### 3.3 재생 엔진 (`app.js`)

핵심은 **모든 대기(sleep)가 하나의 게이트 함수를 통과**하는 것:

```js
let speed = 1;              // 0.5 | 1 | 2
let paused = false;
let runToken = 0;           // 리셋/재시작 시 증가 — 낡은 재생 루프 무효화

async function wait(ms, token) {
  // ms를 작은 조각(예: 50ms)으로 쪼개 반복:
  //  - token !== runToken 이면 AbortError throw → 재생 루프 전체 즉시 종료
  //  - paused면 시간 진행 없이 대기
  //  - 조각마다 speed 반영 (재생 중 속도 변경 즉시 적용)
}
```

- `runScenario(scenario)` 는 시작 시 `token = ++runToken` 을 캡처하고 모든 `wait`/타이핑 루프에 전달한다.
- **리셋** = `runToken++` 후 초기 UI 상태 복원 (스테퍼 1단계, 노드 비활성, 로그/탭 초기화, 버튼 활성화). 진행 중이던 루프는 다음 `wait` 조각에서 스스로 죽는다.
- **일시정지** 중에도 탭 전환은 가능해야 한다 (발표자가 화면 짚으며 설명).
- 타이핑 연출도 `wait` 게이트를 쓰므로 일시정지·속도가 코드 스트림에도 그대로 적용된다.

### 3.4 페이싱 (1x 기준, 목표 약 90초)

| 단계 | 시간 | 주요 연출 |
|---|---|---|
| 1. Intent & Planning | ~15초 | 프롬프트 수신 로그 → 기획서 섹션이 하나씩 등장 |
| 2. Sub-Agent Allocation | ~10초 | 토폴로지 연결선 애니메이션, 노드 3개 활성화 |
| 3. Code Generation | ~30초 | Code Stream 탭 자동 전환, 파일 2~3개 교차 타이핑 |
| 4. E2E Verification | ~25초 | 커서 조작 → 실패 → 자가치유 → 재실행 → 전체 통과 |
| 5. Final Product | ~10초 | 상태등 녹색, 최종 앱 프리뷰 탭 전환 |

시간 값은 단계별 상수 테이블로 두어 촬영 리허설 후 손쉽게 미세조정할 수 있게 한다.

## 4. UI 변경 사항 (`index.html` / `styles.css`)

1. **재생 컨트롤 바** — 파이프라인 스테퍼 옆(우측)에 배치:
   ⏸ 일시정지/▶ 재개 토글, 속도 버튼 그룹(0.5x·1x·2x, 현재 값 하이라이트), ⟳ 리셋.
   재생 전에는 컨트롤 비활성(리셋 제외), 재생 시작 시 활성.
2. **Code Stream 탭 신설** — 기존 탭(📝 기획서 / 🌐 E2E 테스트 / ✨ 최종 앱)에 "💻 Code Stream" 추가.
   - 패널 안에 파일 창: 에이전트 색상 헤더(에이전트명 + 파일명) + 코드 영역.
   - 코드는 문자 단위(수 문자씩 청크) 타이핑, 깜빡이는 커서 표시.
   - 파일 창 2개를 세로로 나란히 배치하고, 두 에이전트가 각자의 창에 번갈아 타이핑해 병렬 작업 느낌을 준다.
   - 구문 강조는 간단한 정규식 수준(키워드/문자열/주석 3색)이면 충분. 외부 라이브러리 금지.
3. **기획서 점진 렌더링** — `planSections`를 섹션 단위로 페이드인.
4. **프리셋 칩 동작 확장** — 칩 클릭 시 프롬프트 문구 교체 + 활성 시나리오 전환(칩 하이라이트).
   직접 타이핑한 임의 프롬프트로 시작하면 현재 선택된 시나리오로 재생하되 프롬프트 문구만 로그·기획서에 반영.
5. 토폴로지 그래프, 터미널 로그, 5단계 스테퍼, 전체 다크 테마는 v1 유지.

## 5. 시나리오 콘텐츠 3종

공통 뼈대(기획서 3섹션, 코드 파일 2~3개, 테스트 실패→치유 드라마, 최종 목업)에 주제별 내용:

| | habit (습관 트래커) | kanban (칸반 보드) | crypto (암호화폐 대시보드) |
|---|---|---|---|
| 코드 파일 | styles.css(UI), app.js(Dev) | board.css(UI), kanban.js(Dev) | dashboard.css(UI), portfolio.js(Dev) |
| 테스트 조작 | 습관 입력 → 추가 클릭 | 카드 생성 → 드래그&드롭 | 시세 갱신 → 합산 확인 |
| 실패 연출 | LocalStorage null 참조 | 드롭존 dragover 핸들러 누락 | 부동소수점 반올림 오차 |
| 치유 패치 | 빈 배열 폴백 초기화 | preventDefault 핸들러 추가 | 정수 센트 연산으로 변경 |
| 최종 목업 | 스트릭·달성률 카드 + 습관 목록 | 3컬럼 보드 + 카드 + 다크모드 뱃지 | 시세 테이블 + 보유자산 요약 + 미니 차트(CSS) |

최종 목업은 v1처럼 정적 HTML이되 체크박스 등 가벼운 상호작용 요소를 포함한다.

## 6. 오류 처리 (촬영 사고 방지)

- 재생 중 시작 버튼 중복 클릭 무시 (v1 유지).
- 리셋은 언제 눌러도 안전: 진행 중 타임라인 즉시 중단 + 초기 화면 복원 + 바로 재시작 가능.
- 재생 중 프리셋 변경은 무시(버튼 비활성) — 중간에 시나리오가 뒤섞이는 사고 방지.
- 일시정지 상태에서 리셋 가능해야 함 (pause 게이트에 갇히지 않도록 토큰 검사를 pause 루프 안에서도 수행).

## 7. 검증 (촬영 리허설 체크리스트)

빌드·테스트 인프라가 없는 정적 데모이므로 브라우저 수동 검증으로 한다:

1. 시나리오 3종 각각 끝까지 자동 재생 — 기획서/코드/테스트/최종앱이 주제와 일치하는지.
2. 각 속도(0.5x/1x/2x)에서 재생, 재생 중 속도 변경 즉시 반영 확인.
3. 각 단계에서 일시정지 → 탭 전환 → 재개가 정상인지.
4. 재생 중·일시정지 중 리셋 → 즉시 재시작이 정상인지 (잔여 로그·타이핑 유령 출력 없어야 함).
5. 1x 전체 러닝타임이 80~100초 범위인지.

## 8. 비범위 (Non-Goals)

- 실제 AI/LLM 연동 없음 — 전부 스크립트된 연출.
- 임의 프롬프트에 대한 진짜 반응형 콘텐츠 생성 없음 (프롬프트 문구 삽입 수준만).
- 모바일 반응형 불필요 — 촬영은 데스크톱 16:9 전체화면 기준.
- 빌드 도구·외부 라이브러리·프레임워크 도입 없음.
- 영상 편집·녹화 기능 없음 (녹화는 OBS 등 외부 도구 몫).
